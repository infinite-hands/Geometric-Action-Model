# requirements.txt is the LIBERO/LIBERO-Plus environment and CANNOT be used here.
# It pins the simulator stack, and three of those pins are irreconcilable with
# lerobot -- which docs/pretraining-data.md itself tells you to install for the
# gam_pretraining loader:
#
#     requirements.txt            lerobot 0.5.0
#     numpy==1.26.4               numpy>=2.0.0,<2.3.0
#     huggingface_hub==1.10.1     (0.4.4 wanted <0.36.0; 0.5.0 wants >=1.0.0, so 0.5.0 is fine)
#     torchvision==0.20.1 (Dockerfile) torchvision>=0.21.0
#
# A single dependency resolution refuses that outright. The documented
# `pip install -r requirements.txt && pip install lerobot==0.4.4` only appears to
# work because the second install silently overwrites pins from the first, which
# leaves an environment nobody has actually validated.
#
# This file resolves it the honest way: the closed-loop LIBERO evaluation is off
# on this path (training.eval_every is set beyond max_steps in configs/training/yam/),
# so the simulator is not installed at all, and numpy is left to the resolver.
#
# DROPPED, all LIBERO-simulator-only and all imported lazily inside functions
# that this path never calls -- robosuite, mujoco, gym, gymnasium, bddl,
# Farama-Notifications, easydict, future, PyOpenGL, Wand, moviepy -- plus numba,
# llvmlite, scikit-image and scipy, which src/ never imports at all.
#
# KEPT even though they look like eval-only: matplotlib, plotly, imageio and
# imageio-ffmpeg back robot/viz/visualization.py, which training calls every
# `vis_every` steps; and wandb, which train_robot.py imports lazily regardless of
# whether --wandb was passed.
# =============================================================================
